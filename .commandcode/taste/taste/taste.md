# Taste
- Prefers long-running servers/services (e.g., Langflow) to be launched in the background so they keep running while the session continues, and expects the agent to verify they're actually up (e.g., hit the health endpoint / check the port) before reporting success. Confidence: 0.7
- Commits new work incrementally by project subfolder (e.g., each N8N workflow under `07_N8N_Workflows/` gets its own commit) and expects each commit to be pushed to their GitHub remote ("my repo"). Confidence: 0.8
- Treats markdown skill files in the repo (e.g., `resume_job_tailoring_skill.md`) as authoritative instructions and expects the agent to read them and apply them to batch input data (e.g., a CSV of job openings) to produce outputs. Confidence: 0.7
- Expects batch-generated outputs (one variant set per input record) to land in a chapter-level `output/` folder, organized into subfolders/files named per company/entity with the company name in the filename. Confidence: 0.6
- Issues brief, imperative task requests (e.g., "commit 02_GmailSchedular into my repo"; "commit ...Chapter_04_JobkitAI and ...Chapter_05_JobTrackerAI into my repo"; "create the multiple version ... apply the skill with the jobs"; "`C:\...\Chapter_05_JobTrackerAI run this code`") without extra detail, expecting the agent to inspect state and fill in the rest. Confidence: 0.95
- Wants the plan written to a `plan.md` file inside the deliverable's own directory (e.g., the agent folder next to the generated file), so it ships as repo documentation alongside the artifact, rather than only being discussed in chat. Confidence: 0.75
- Expects research to happen before building — e.g., "first research which cheaper model I can use" — with findings (options, trade-offs) surfaced before code is produced. Confidence: 0.7
- Cost-conscious about LLM API selection: asks for the cheapest model that can do the job, expects per-request cost reasoning (pricing per token/image) and a practical cheaper fallback. Confidence: 0.7
- Organizes work in per-chapter project folders (e.g., `Chapter_08_N8N/`) with generated agent artifacts under an `Agents/` subfolder, named with a zero-padded numeric prefix matching the chapter/agent number (e.g., `08_Screenshot_To_Bugreport_AIAgent.json`, then `09_Requirement_To_Testcase_AIAgent.json`). Confidence: 0.8
- When requesting a new artifact in an existing series, points at the sibling artifact already in place (e.g., opens `08_...json` in the IDE) and expects the new one to follow the same established conventions — numbered naming, credential placeholders (no hardcoded keys), setup/notes sticky notes, structured-output parsing. Confidence: 0.6
- When they open an existing artifact in the IDE and ask for a different/integrated version, expects that same file to be rewritten in place (same filename and naming conventions) rather than a parallel new file being added. Confidence: 0.55
- When running browser/UI automation, likes to watch the execution visibly in the browser (headed mode) rather than headless — asks the agent to "run and show the execution on browser". Confidence: 0.6
- For automation workflows, prefers event-driven triggers that fire automatically off the source system (e.g., Jira issue created/updated) over manual on-demand webhook calls, and prefers non-invasive write-back — commenting on the existing ticket rather than creating a new issue per result. Confidence: 0.6
